# OpenSSF Best Practices level-0 self-assessment proposal

> Draft review material only. This is not a badge, certification, compliance statement, penetration-test result, security attestation, or claim of achievement. No public enrollment or external submission has been made.

## Scope and interpretation

- Criterion source: local official `criteria/criteria.yml`, level key `0`, in the OpenSSF Best Practices Badge repository. The source contains exactly 67 unique criteria: 43 MUST, 10 SHOULD, and 14 SUGGESTED.
- Proposal-field/status source: the official `.bestpractices.json` documentation, automation-proposal documentation, current application field validator, and `docs/self.json`. Current criterion IDs from `criteria.yml` are used rather than legacy names visible in the old example export.
- Repository inspection date: 2026-07-23. Read-only GitHub inspection reported a public repository with default branch `main`, zero open or closed issues, and zero releases. The worktree contains additional security workflows that are not yet published on `main`; no workflow conclusion or external security result is claimed for them.
- `Review status` is the proposed human answer after completing the action in `Owner / reviewer need`. It is not a current assertion when `Adapter status` is `omitted`.
- The adapter intentionally omits human-only, release-gated, scan-result, and full-history claims. Its proposed statuses are paired with justifications and use only recognized current criterion field names.
- Review-status totals: 59 Met, 5 N/A, 3 Unmet. Adapter totals: 48 Met, 4 N/A, 3 Unmet, 12 omitted.

## Publication conditions

1. Every `blob/v0.1.0` or `tree/v0.1.0` link below is intentionally release-dependent. It becomes stable evidence only if Main publishes the real `v0.1.0` tag from the reviewed contents. Until then, those URLs may not resolve.
2. Main-branch URLs are used for CodeQL, dependency review, Scorecard, CI, and other files that GitHub must inspect before a release. Publish and enable those files, then observe the relevant result before making any result-dependent assertion.
3. GitHub private vulnerability reporting, Dependabot alerts/security updates, secret scanning, and push protection are owner-reported as enabled. Their private settings and alert state require repository-owner confirmation immediately before submission.
4. Public badge enrollment remains pending. Do not add a badge or achievement statement until a human has resolved every remaining gate and the public service has accepted the assessment.

## Material limitations

- Coverage is 70.29% lines and 62.35% branches (65.74% functions; 68.09% statements), so `test_most` is Unmet.
- CodeQL is configured only for JavaScript/TypeScript and GitHub Actions. It does not scan authored Civet. Biome, TypeScript/Civet checks, and tests protect other quality boundaries but are not mislabeled as equivalent vulnerability SAST.
- No DAST/web scanner or fuzzer exists, and measured branch coverage is below the official 80% automated-test-suite alternative. `dynamic_analysis` and `dynamic_analysis_enable_assertions` are Unmet; `dynamic_analysis_fixed` is N/A because no qualifying channel produced a finding.
- Application-owned cryptography is separated from deployment/provider responsibilities. Web/Node Crypto and Better Auth own HMAC, CSPRNG, and password hashing; Cloudflare or another operator owns TLS certificates, cipher negotiation, and forward secrecy.
- The public history contains zero issues, and the maintainer confirmed no GitHub repository advisory on 2026-07-23. Response rows describe only that dated history and promise no acknowledgement time, remediation time, or SLA.
- The maintainer-confirmed advisory/NVD check is recorded in the forthcoming 0.1.0 changelog. This review did not independently rerun it and does not represent it as a penetration test, general scan, or proof that the software is vulnerability-free.

## Remaining human-review fields

The adapter omits these 12 status/justification pairs rather than converting uncertainty into an assertion:

- Release publication: `version_unique`, `version_semver`, `version_tags`, `release_notes`, `release_notes_vulns`.
- Personal knowledge: `know_secure_design`, `know_common_errors`.
- Credential state: `no_leaked_credentials`.
- Static-analysis execution/results: `static_analysis`, `static_analysis_common_vulnerabilities`, `static_analysis_fixed`, `static_analysis_often`.

A human must also re-check the dated evidence windows for `report_responses`, `enhancement_responses`, `vulnerability_report_response`, `vulnerabilities_fixed_60_days`, and `vulnerabilities_critical_fixed`; confirm private vulnerability reporting remains enabled; verify the release revision's build/CI; and reconfirm Better Auth 1.6.24 password hashing before external submission.

## Narrow verification contract

Validation for this documentation-only proposal is structural: parse JSON; compare ledger IDs/categories with official level-0 criteria; reject unknown fields/statuses; require paired non-empty justifications; require URLs for proposed Met rows whose criterion declares `met_url_required`; map release-content links back to existing local paths; and reject badge/achievement claims. It does not run project-wide formatting, linting, builds, tests, scanners, or deployment commands.
