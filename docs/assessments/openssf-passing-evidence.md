# OpenSSF Best Practices Passing evidence

> Public project [13782](https://www.bestpractices.dev/en/projects/13782) earned the OpenSSF Best Practices Passing badge at 100% on 2026-07-25. This ledger records the evidence and material limitations behind that self-assessment; it is not a penetration-test result, warranty, or claim that the application is vulnerability-free.

## Scope and interpretation

- Criterion source: local official `criteria/criteria.yml`, level key `0`, in the OpenSSF Best Practices Badge repository. The source contains exactly 67 unique criteria: 43 MUST, 10 SHOULD, and 14 SUGGESTED.
- Adapter-field/status source: the official `.bestpractices.json` documentation, automation-proposal documentation, current application field validator, and `docs/self.json`. Current criterion IDs from `criteria.yml` are used rather than legacy names visible in the old example export.
- Repository inspection date: 2026-07-25. GitHub reports a public repository with default branch `main`, zero public issues, and a published [v0.1.0 release](https://github.com/jeffscottward/darkfactory/releases/tag/v0.1.0). The exact tagged revision passed all five CI lanes, both CodeQL analyses, and OpenSSF Scorecard before publication.
- `Review status` records the final human-reviewed answer submitted to the public project. `Adapter status` records only what the conservative local automation adapter emits.
- The adapter intentionally omits human-only, release-gated, scan-result, and full-history claims even though those fields were separately reviewed and submitted through the official service.
- Official submitted totals: 63 Met, 4 N/A, 0 Unmet, and 0 Unknown. Conservative local adapter totals remain 52 Met, 3 N/A, 0 Unmet, and 12 omitted.

## Material limitations

- The deterministic Vitest scope now measures 87.68% lines and 84.08% branches (84.09% functions; 86.29% statements), so it exceeds the official 80% branch-coverage alternative for qualifying automated tests. Integration and browser lanes remain separate and are not included in those percentages.
- CodeQL is configured only for JavaScript/TypeScript and GitHub Actions. It does not scan authored Civet. Biome, TypeScript/Civet checks, and tests protect other quality boundaries but are not mislabeled as equivalent vulnerability SAST.
- The assertion-bearing Vitest suite qualifies as dynamic analysis through the official 80% branch-coverage alternative; Playwright provides additional separately verified runtime behavior. This does not claim DAST scanner or fuzzing coverage and does not prove the software vulnerability-free.
- Application-owned cryptography is separated from deployment/provider responsibilities. Web/Node Crypto and Better Auth own HMAC, CSPRNG, and password hashing; Cloudflare or another operator owns TLS certificates, cipher negotiation, and forward secrecy.
- The public history contains zero issues, and the maintainer confirmed no GitHub repository advisory/report on 2026-07-25. Response rows describe only that dated history and promise no acknowledgement time, remediation time, or SLA.
- The published 0.1.0 changelog lists eight dependency advisories fixed before release. No publicly known DarkFactory project runtime vulnerability with a CVE or similar identifier was identified; the official `release_notes_vulns` criterion excludes dependency vulnerabilities and therefore uses N/A here. These bounded checks are not a penetration test, general vulnerability scan, or proof that the software is vulnerability-free.

## Conservative local adapter omissions

The public assessment answers all 67 criteria after human review, but the machine-oriented adapter continues to omit these 12 status/justification pairs rather than convert external or human judgment into repository-computable facts:

- Release publication: `version_unique`, `version_semver`, `version_tags`, `release_notes`, `release_notes_vulns`.
- Personal knowledge: `know_secure_design`, `know_common_errors`.
- Credential state: `no_leaked_credentials`.
- Static-analysis execution/results: `static_analysis`, `static_analysis_common_vulnerabilities`, `static_analysis_fixed`, `static_analysis_often`.

The public service records the reviewed values; future renewals must refresh issue/report windows, owner-visible security settings and alerts, CI/scanner results, dependency state, release evidence, and applicable human attestations.

## Narrow verification contract

Validation for this evidence is structural: parse JSON; compare ledger IDs/categories with official level-0 criteria; reject unknown fields/statuses; require paired non-empty justifications; require URLs for Met rows whose criterion declares `met_url_required`; map immutable release-content links to existing repository paths; and require the official project URL for the achieved state. It does not substitute for the externally hosted public assessment, repeat a penetration test, or claim future revisions inherit the result.
